# Памятка по Calendar MCP

## Ответственность

Сервис выполняет подтверждённые календарные команды. Он не распознаёт речь, не принимает решение о
подтверждении и не хранит состояние action workflow. Сейчас доступен только fake-calendar.

## Границы слоёв

- `controller` содержит MCP/HTTP и вызывает один метод service;
- `service` содержит сценарий и идемпотентность;
- `repository` хранит события и позже получит адаптеры провайдеров;
- `model` не зависит от MCP, FastAPI и хранилища;
- `config` читает переменные окружения;
- новый календарь добавляется новой реализацией repository, без копирования service.

Test API `/test/events` включается только переменной `CALENDAR_TEST_API_ENABLED=true`. Не включай его в
публичном окружении; при включении обязателен `CALENDAR_TEST_API_KEY`. Не пиши attendee email и описание
встречи в обычные логи.
Не отключай MCP DNS-rebinding protection: внешние имена добавляются через `CALENDAR_MCP_ALLOWED_HOSTS`.
Не принимай `tenant_id` аргументом MCP tool: identity приходит только из проверенного OIDC-токена.
Memory repository разрешает только один процесс и одну реплику.

## Простые имена

Используй короткие английские слова: `create`, `find`, `event`, `calendar`, `result`, `error`.
Сложные термины объясняй в русской документации.
